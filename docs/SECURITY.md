# Security

PR-0 is a local development tool, not a multi-user or public service. The API does not authenticate callers; the default bind address is loopback. Do not bind it to a public or shared interface, and do not rely on CORS as an authorization control. Restrict access to the machine and workspace that own the process.

The server binds to `127.0.0.1` by default and permits the configured frontend origin only. Request bodies are size-limited and parsed with Zod at API boundaries. Registered projects can optionally be restricted beneath `PR0_WORKSPACE_ROOT`; registration resolves symlinks before checking the boundary and requires an existing directory.

Filesystem access supports explicit UTF-8 reads and approval-gated writes. Absolute paths, lexical traversal, symlink escapes, symbolic-link overwrite targets, directories, and binary reads are rejected. Writes must target an existing, resolved directory within the registered workspace and default to no-overwrite behavior. Supervised and ask-first writes become persisted pending operations; approving the related request executes it server-side. Model-requested writes reject sensitive paths and credential-like content before queuing. Their approval preview contains only the proposed path, overwrite mode, and at most 20,000 characters of content; the full pending-operation payload is not returned by the approval feed. The UI renders preview content as text, not markup. Rejecting or cancelling a still-pending proposal leaves the target unchanged. Once an approval has claimed a write for execution, cancellation returns a conflict until that write finishes; if the server restarts while the task is waiting, recovery fails the task and invalidates its pending agent-write approval rather than resuming it.

Terminal commands use direct process spawning with `shell: false`; the initial allowlist is `node`, `npm`, `npx`, and `git`. Commands are workspace-scoped, receive no stdin, have bounded output, use a configurable timeout, and require approval in supervised or ask-first mode. Active child processes are terminated during server shutdown.

Model output, repository files, terminal output, and web pages must be treated as untrusted data. Tool permissions, rather than model instructions, are the authority boundary.

Public page research and browser automation are explicitly user-initiated and read-only. They accept HTTPS URLs on the default port, reject IP-literal and local/special-use destinations, resolve every hostname and pin the connection to a validated public address, reject redirects, send no cookies or credentials, accept only HTML/plain text, and limit response size and time. Playwright runs in a fresh headless context with JavaScript and service workers disabled; only bounded top-level GET navigations are fulfilled through the same validated fetch helper. Subresources, forms, downloads, popups, submit buttons, and non-text/password fields are blocked or removed. Selector actions are limited to a small validated CSS subset, and browser tools are not exposed to the model loop. Retrieved HTML is never inserted as active application markup.

This public-page browser feature is not an AI-provider login integration. PR-0 does not sign in to consumer AI websites, automate their chat interfaces, copy browser cookies/tokens/local storage, or impersonate official clients. Current reviewed OpenAI consumer terms prohibit automated/programmatic extraction; Anthropic consumer terms reserve automated access for API-key access or explicit permission; Google terms prohibit automated access that violates machine-readable site instructions and do not explicitly authorize automating Gemini Apps as a model API. See [PROVIDERS.md](PROVIDERS.md). The supported no-separate-paid-key model route is a local Ollama daemon through its documented HTTP API. Its status probe only requests the operator-configured `/api/tags` endpoint with a short timeout and does not transmit credentials.

Git patch and history APIs use fixed Git arguments, bounded output, and omit paths flagged by the sensitive-file detector; patches in other files may still contain secrets. Checkpoints are app-namespaced annotated tags created only from a clean worktree. Rollback requires a preview, a matching current HEAD, a clean worktree, an explicit UI confirmation, and a backup tag; it refuses collisions with ignored files and never runs `git clean`.

The model tool loop exposes only registered tools, validates inputs before dispatch, caps iterations, and truncates results. Model-readable filesystem access rejects common secret files such as `.env*`, SSH keys, credential files, and private key files. Provider API keys are accepted only by the server process environment and are not persisted or returned through provider status endpoints.
